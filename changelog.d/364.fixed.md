**`--dwell-template-table` now guards against a table built for a different `motif_offset` than the run using it.** The TSV's `position` column is counted from the focus base, but a bare `aa, position, dwell_mean` table never recorded which `motif_offset` that was, so pairing a table built at one offset with a corpus/model at another silently misaligned every lookup (every row still produced a finite ratio, so nothing raised on its own). The table may now carry `# motif_offset: N` / `# motif: ...` header lines recording what it was built against; `model train`, `eval test`, `model calibrate` and bundle predict all check the table's recorded offset against the run's own and raise on a mismatch, warning instead when an unlabelled table is paired with a non-default `motif_offset`. The checkpoint's `config.json` now also records the table's own `dwell_template_motif_offset`/`dwell_template_motif` for provenance.
