**The ONNX export contract now describes a multiclass checkpoint's output correctly instead of always claiming a single BCE logit.** `leech model export --format onnx` hardcoded the sidecar's output block to `shape: ["batch", 1]` and a sigmoid convention even for a `num_out > 1` checkpoint (`loss_type: cross_entropy`), whose graph actually emits `(batch, num_out)` and expects a softmax — a consumer trusting the sidecar applied the wrong transform silently. `leech.onnx_export.describe_output` now derives the block from the checkpoint's `num_out`: unchanged for `num_out <= 1`, and for `num_out > 1` a softmax convention with `shape: ["batch", num_out]`, the class order read from `label_map` (`"classes": null` with a warning if the checkpoint has none — refused outright if `label_map`'s length disagrees with `num_out`), and a present calibration's method named (applying it is still the consumer's job). `export_single_model_onnx` also checks the exported graph's actual output width against `num_out` before writing the contract, and raises if they disagree.
