**`--dwell-template-table` no longer ties a checkpoint to the CLI's original (often repo-relative) path.** `model train` now copies the TSV into `<output_dir>/dwell_template_table.tsv` and records the bare filename in `config.json`, alongside the original absolute source path and a sha256 for provenance. `eval test`, `model calibrate`, and bundle predict resolve the recorded path against the checkpoint directory via the new `leech.model_loading.resolve_dwell_template_path` (falling back to the CWD-relative path, with a warning, for a pre-existing checkpoint). `model bundle` embeds the table as bytes in the bundle file itself when the source checkpoint has one, so a bundle -- a single `.pt` file -- no longer depends on that checkpoint directory surviving; `bundle-info` reports whether a table is embedded.
