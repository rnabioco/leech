**`leech predict --workers N`/bundle predict on a checkpoint trained with `--dwell-template-table` and a stored feature window wider than the model's k-mer window.** The `num_workers > 0` pool path (`_inference_worker`) narrowed each chunk's feature array with no knowledge of the dwell template, then appended the template afterward in the main process keyed to the *stored* window's origin -- wrong by `(-kmer_context + dwell_offset) - feature_start` columns whenever narrowing actually did anything. The template is now applied inside the worker, before narrowing, the same order training and every other extraction path already use; the post-hoc appends in `run_inference` and `run_bundle_inference` are gone.
