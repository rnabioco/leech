- **`data prepare --signal-context-bases` with `--seq-encoding signal_kmer` (the default) could scatter a chunk's k-mer sequence identity at the wrong signal positions.** Whenever a read's requested base-defined window was wider than `--signal-len`, both prepare backends built `seq_to_sig_map` from the pre-crop request rather than the window `place_window` actually placed the signal in — a shift of up to hundreds of samples, invisible to the Python/Rust backend-parity suite because both backends shared the identical bug. Fixed in the Python extractor and the Rust `data prepare` path; `leech predict`'s Rust path has the same root cause in the pinned upstream `escapepod-signal` crate and is tracked separately (rnabioco/escapepod-rs#388) pending an upstream fix.
