**`encode_signal_kmer`'s pure-Python fallback (used by any install without the `leech[rust]` extra) no longer crashes with `IndexError` on a chunk whose k-mer context runs off the edge of a read.** The pinned `escapepod-signal` crate treats a `sequence_ints` index past the end of the array as "nothing to encode at this k-mer position," matching an explicit upstream test (`missing_context_is_skipped_not_padded`); the Python fallback indexed unconditionally instead and raised. Invisible until now because every CI job and dev environment has the Rust extension built, so the fallback was never exercised — new tests force `HAS_RUST=False` to close that gap for good.
