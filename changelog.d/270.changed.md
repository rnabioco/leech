**Training recipe fields are now backed by one `TrainConfig` dataclass.** `train_model` and `Trainer` accept an optional `cfg: TrainConfig` (grouped into `OptimConfig`, `SchedulerConfig`, `AugmentConfig`, `AuxHeadConfig`); when omitted, one is built from the existing individual keyword arguments so every current caller keeps working unchanged. `handle_train` now builds `cfg` once instead of re-listing ~35 options. `config.json`'s contents and every default are unchanged.
